# 《猫忍不住》v1.2.24
## 首轮纸面平衡模拟 / Balance Sheet v1

> 目的：在没有实际 Runtime / 玩家数据之前，对 v1.2.23 的 12 关测试基线做一次“纸面跑局”，找出明显的节奏断层、单机制依赖和三猫爪条件冲突。
>
> **重要说明：** 本文中的“模拟结果”是基于当前 GDD / System Spec / Level Bible 的参数关系做出的设计假设，不是实际玩家统计，也不是 Godot Runtime 实测结果。实际冻结必须以试玩数据替换。

---

# 1. 结论摘要

## 1.1 最明显的问题：L08 → L09 难度时长出现回落

v1.2.23 原基线：

```text
L08 目标 85–130s
L09 目标 70–110s
```

这会造成第三章开场在玩家刚适应多线程规划后，反而回到较低的时间压力。

**修正：**

```text
L09 目标 90–120s
L09 首通 110–150s
L09 三爪 ≤100s
```

同时不增加新机制，只通过雷雨环境、忍者加速、事件间距缩短制造压力。

## 1.2 L04 → L05 是第一处明显的“认知跃迁”

L04 教的是顺序；L05 引入 Q 搬运。

因此真正增加的是：

```text
排序
+
空间移动
+
携带速度惩罚
```

这里不能单纯压缩时间，否则玩家会把新机制理解成“赶紧跑”，而不是“正确运输”。

**建议：L05 保留较宽首通时间，优先观察搬运理解率。**

## 1.3 L08 → L11 是第二次复杂度堆叠

```text
L08 = 守卫线 + 狗线 + 运输线
L09 = 高压环境
L10 = 连锁事故
L11 = 三线程持续管理
```

这里不应该每关同时增加“更快 + 更多事件 + 更窄窗口”。

建议：

```text
L08 学会多线程
L09 只提高节奏
L10 提高预测难度
L11 提高并发数量
```

## 1.4 L12 不宜继续靠纯时间压难

Boss 已经存在：

- Crane
- Gourd
- Phase 2 Caltrop
- Emergency Rescue

因此 L12 的难度主来源必须是：

> **信息组织 + 战中切换**

而不是简单把时间压得非常短。

# 3. 单关主调参杠杆

原则：每关只允许 1 个“第一调参变量”。如果失败率过高，先改主杠杆，不同时修改三个以上变量。

| 关卡 | 主调参变量 | 次调参变量 | 不建议优先动 |
|---|---|---|---|
| L01 | EventPoint 距离 | 犹豫窗口 | 移速 |
| L02 | 事件间净空时间 | 疾跑消耗 | 疾跑速度 |
| L03 | 怀疑累积速率 | 卖萌有效时机 | 视野半径 |
| L04 | 事件状态依赖 | 捷径位置 | 忍者速度 |
| L05 | 搬运距离 | 狗感知圈 | CARRY_SPEED_MULT |
| L06 | Dog → Guard 联动窗口 | 鱼持续时间 | Dog 移速 |
| L07 | Guard A → B 换岗延迟 | 回岗时间 | 猫移动速度 |
| L08 | 三线程空间距离 | 资源数量 | 事件数量 |
| L09 | 事件间距 / 读图遮挡 | 雷雨视觉强度 | 加新机制 |
| L10 | 连锁触发半径 | 爆炸窗口 | 猫移速 |
| L11 | 并发窗口重叠率 | Shortcut 位置 | 全局减速 |
| L12 | Boss Phase 2 操作窗口 | Crane/Gourd 准备位置 | 单纯缩短 Boss 总时间 |

# 4. 纸面跑局检查

## L01–L04

### L01

理论上应形成：

```text
观察 → 提前移动 → E → F → E → Goal
```

**风险：** 玩家可能把“移动”误认为唯一关键，忽略第一关在教“先观察”。

处理：不继续加时间压力；保持读图阶段清晰。

### L02

核心应形成：

```text
Event A → 继续前进 → Event B
```

**风险：** 玩家无脑 Shift。

处理：优先扩大/缩小事件空间，而不是增加疾跑速度。

### L03

必须明显感受到：

```text
被看见 ≠ 失败
动作被看见 = 怀疑
卖萌 = 清除
```

**风险：** 若玩家不理解“为何涨怀疑”，降阈值没有意义，应先修反馈。

### L04

第一章真正的解谜峰值。

**风险：** 两条路线如果差异只是长度，就没有“排序题”的价值。

要求：至少一个 WorldState 差异真正改变下一事件状态。

# 5. L05–L08 纸面跑局

## L05

Q 搬运首次加入后，猫的有效速度：

```text
90 × 0.85 = 76.5 px/s
```

这是有意存在的压力。

**注意：** 不建议首轮就提高 CARRY_SPEED_MULT，因为原设计希望携带本身制造“送货紧张感”。

## L06

Dog 双解：

```text
鱼引狗 = 标准
自己当诱饵 = 高风险
```

两者必须共享同一个世界结果，否则高风险解只是彩蛋。

## L07

Guard A / B 必须让“8 秒巡逻周期 / 约 6 秒回归”成为玩家可读的节奏，而不是隐藏参数。

如果大量失败来自纯粹算不准时间，优先增加视觉节拍提示，而不是放宽所有窗口。

## L08

这是第二章最高复杂度关。

**纸面风险：** 守卫线、狗线、运输线同时存在时，玩家可能随机跑图。

QA 重点：

> 玩家是否是在“计划”，还是在“救火”

如果后者占绝大多数，说明并发窗口过密。

# 6. L09–L12 纸面跑局

## L09

第三章不新增操作。

主要压力：

```text
雷雨
+
忍者速度提升
+
较短的安全间距
```

因此它应该感觉更紧，但不是让玩家学新东西。

## L10

Dynamite 的核心不是“不要碰”，而是：

```text
提前判断爆炸会改变谁的位置
```

如果玩家只学到“别碰”，需要返工因果反馈。

## L11

三线程关。

建议定义三个同时存在的“时间槽”：

```text
Guard Window
Dog Window
Environment Window
```

玩家不要求同时看三个 UI，只要求地图布局让它们产生交叉。

## L12

Boss 的最小信息链应当是：

```text
Boss Start
→ Phase 1
→ Phase 2 Charge
→ Caltrop Window
→ Phase 3
```

Emergency 只作为失败保护，不应成为正常路线。

# 7. 三猫爪冲突检查

## 7.1 当前规则没有发现直接逻辑冲突

仍然保持：

```text
Paw 1 = 完成任务
Paw 2 = 完成 + HP≥2 + Suspicion<80
Paw 3 = 完成 + HP≥2 + 表现条件门槛
```

## 7.2 需要关注的体验冲突

### L06

高风险路线如果非常容易导致 HP / Suspicion 损失，玩家可能自然放弃 Risky 风格。

**解决方向：** 不给 Risky 额外数值奖励，而是确保至少存在一个事件组合，让高风险路线在时间或捷径上明显占优。

### L12

Emergency Rescue 固定 1 爪，因此不能让它成为“最稳定的一爪速通”。

**解决方向：** Emergency 增加明显的时间损失 / 结算标签，但不额外惩罚资源。

# 8. 建议首轮 Playtest 样本

第一轮仍建议：

> **8 名无体验历史玩家**

但从 v1.2.24 开始，每人不只跑一次。

建议：

```text
Round 1：自然首通
Round 2：同关重玩
Round 3：明确追求 3 猫爪
```

这样可以分离三个问题：

```text
第一次看不懂
第一次会了但不熟
已经会了但优化不出来
```

# 10. 纸面风险排名

这不是玩家评分，而是开发风险优先级。

1. **L08：多线程过密**
2. **L12：Boss 主动性不足**
3. **L07：因果关系不够可读**
4. **L03：怀疑系统反馈不充分**
5. **L09：环境效果遮挡信息**
6. **L05：Q 搬运只变成慢**
7. **L10：炸药只变成“禁碰”**
8. **L04：两条路线差异不足**

这些是制作风险序列，不代表关卡质量评价。

# 11. 下一轮冻结原则

在得到首轮真实试玩数据之前：

```text
不继续新增核心机制
不继续增加新按键
不继续扩张到 L13+
不提前做复杂随机系统
```

先把 L01–L12 的：

```text
可读性
→ 节奏
→ 因果
→ 三爪
→ Boss 主动性
```

验证完，再做大规模内容扩展。
