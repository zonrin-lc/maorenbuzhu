# 《猫忍不住》v1.2.25
## 首通体验 / 三猫爪 / SAFE-BALANCED-RISKY 测试设计

> 本版建立在 v1.2.24 Balance Sheet v1 上。目标不是继续增加系统，而是验证 12 个主线关卡是否都能形成可理解、可复现的三种打法。
>
> 说明：本文件定义的是**测试假设与验收方法**，不是实际玩家数据。只有完成真实试玩后，才能冻结路线成功率、猫爪达成率和最终数值。

---

# 1. 测试目标

每一关至少验证四件事：

1. 新玩家能否理解这关的主决策。
2. SAFE / BALANCED / RISKY 三种路线是否都成立。
3. 三猫爪条件是否会鼓励多个解，而不是逼玩家只走一种答案。
4. 失败后玩家能否说出下一次要改变的具体行为。

原则：

```text
先验证“看懂”
→ 再验证“做出”
→ 再验证“做得漂亮”
```

---

# 2. 三路线定义

## SAFE

目标：低风险、稳定完成。

典型特征：
- 提前处理
- 避免不必要的高风险动作
- 优先保持 Ninja HP
- 允许花更多时间

## BALANCED

目标：时间、风险、联动之间取得平衡。

典型特征：
- 合理使用 Shortcut
- 利用 NPC 联动
- 少量风险
- 追求稳定三爪

## RISKY

目标：极限调度 / 高风险救场。

典型特征：
- 临近事件窗口才处理
- 使用肉身诱饵、战中处理等高风险方案
- 允许局部危险换取时间或更漂亮的连锁

注意：RISKY 不是“故意让忍者掉血刷分”。v1.1 已明确 Ninja HP < 2 时永远不能拿 3 猫爪。

---

# 3. 玩家测试流程

## 样本

第一轮建议 8 名新玩家，第二轮可加入 4 名熟练玩家。

## 每关流程

```text
读图阶段
↓
第一次尝试：不提示解法
↓
记录首次行为
↓
第二次尝试：允许玩家自然重试
↓
询问：下一次准备改变什么？
↓
第三次尝试：观察是否形成主动策略
```

禁止测试员提前说“正确顺序”。

---

# 4. 观察指标

每局记录：

```text
clear
elapsed_time
ninja_hp_final
max_suspicion
paw_count
risk_style
shortcut_used
high_risk_rescue
chain_rescue
first_fail_code
retry_count
event_order_signature
player_explanation
```

额外记录三个行为指标：

### A. 提前行为率

玩家是否在 Ninja 到达事件前主动前往事件点。

### B. 主动策略率

玩家是否在第二次尝试中改变行为顺序，而不是重复原动作。

### C. 解释正确率

玩家能否用一句话说明这关真正考什么。

# 5. 关卡测试卡

## L01《第一份差事》

主决策：提前行动。

### SAFE

```text
读图
→ Tripwire 提前咬断
→ Guard 不做高风险骚扰
→ Crate 提前摆好
→ Ninja 通过
```

验证：玩家是否理解“提前做事”。

### BALANCED

```text
Tripwire
→ 赶到 Guard
→ F 喵叫
→ 赶到 Watergap
```

验证：玩家是否开始形成路线意识。

### RISKY

```text
贴近 Ninja 时间窗处理
→ 用短疾跑抢最后窗口
→ 尽量不浪费移动时间
```

验证：玩家是否能主动制造“差一点”的紧张感。

三爪重点：A/B/C/F。

---

## L02《他总是踩同一个坑》

主决策：连续赶场。

### SAFE

提前处理两个事件，保留体力。

### BALANCED

使用一次疾跑，把两个事件处理窗口串起来。

### RISKY

故意把第二事件留到临界窗口处理，验证最后一秒能力。

主调参：事件间净空时间。

---

## L03《谁在看猫》

主决策：区分“被看见”和“动作暴露”。

### SAFE

尽量让互动动作避开 Ninja 视锥。

### BALANCED

允许一次轻度暴露，用 Ctrl 清怀疑。

### RISKY

在危险窗口内完成动作，再用卖萌化解。

必须验证：玩家不能把“被看到猫”误解为失败。

---

## L04《村口大事故》

主决策：事件顺序。

### SAFE

```text
Guard
→ Tripwire
→ Crate
→ Watergap
```

### BALANCED

```text
Tripwire
→ Guard
→ Shortcut
→ Watergap
```

### RISKY

利用忍者犹豫窗口，延后一项处理并快速跨区补救。

验收重点：两条主解必须都能被玩家发现；不能依赖“唯一正确顺序”。

---

## L05《月夜码头》

主决策：搬运。

### SAFE

鱼肉 / 解毒药提前送到固定位置。

### BALANCED

途中携带 + Shortcut。

### RISKY

在 Ninja 接近后才完成最后一次运输。

验证重点：玩家理解“携带减速”是规划成本，而不是角色手感故障。

---

## L06《狗也能当队友》

主决策：NPC 联动。

### SAFE

鱼引 Dog 离开路线。

### BALANCED

Dog → Guard 联动，利用叫声转移守卫。

### RISKY

猫自己当诱饵，引 Dog 绕场再让 Ninja 通过。

验证重点：RISKY 路线必须被玩家认为是“我设计出来的”，不是碰巧发生。

---

## L07《谁先走》

主决策：换岗因果。

### SAFE

按固定周期处理 Guard A，再等待安全窗口。

### BALANCED

使用 Guard A 的离岗制造 Guard B 的路线缺口。

### RISKY

贴着换岗临界点连续操作，压榨窗口。

核心问题：玩家是否会在第二次尝试主动调整顺序。

---

## L08《最后一班船》

主决策：三线程管理。

### SAFE

先完成最稳定的资源线，再处理 Guard / Dog。

### BALANCED

三线程交错推进，使用 Shortcut。

### RISKY

把至少一项事件留到临界窗口现场救火。

重点：玩家是在“排程”而不是无脑跑图。

---

## L09《雷雨夜》

主决策：在高压环境中保持路线读取。

### SAFE

提前处理事件，减少现场操作。

### BALANCED

结合 Shortcut 与少量疾跑。

### RISKY

在雷雨干扰与 Ninja 加速下压线处理。

验证：第三章压力上升，但核心规则不应重新教学。

---

## L10《炸药不能乱碰》

主决策：预测连锁事故。

### SAFE

提前让 Dynamite 失效。

### BALANCED

利用爆炸改变 NPC / 路线，然后接续下一事件。

### RISKY

压线处理爆炸并利用其制造的窗口。

重点：玩家应理解“炸药是可操纵的环境变量”，而不是单纯的禁区。

---

## L11《越靠近城门越忙》

主决策：多线程持续管理。

### SAFE

按线程顺序逐项清理。

### BALANCED

并行处理两条线程，再回收第三条。

### RISKY

至少一次临界救场，验证高压多线程能力。

如果 8 名新玩家中多数只会全程追着 Ninja 跑，本关需要返工空间关系，而不是直接放宽时间。

---

## L12《守门武士》

主决策：战前准备 + Boss 战中切换。

### SAFE

```text
Crane Ready
→ Gourd Ready
→ Boss
→ 稳定处理 Phase 2 Caltrop
```

### BALANCED

提前准备两机关，战中移动处理蒺藜。

### RISKY

保留至少一项资源到临界阶段，再进行战中操作；必要时 Emergency Rescue 只作为保底。

必须验证：玩家不会把 Boss 战理解成“提前全部做完然后观看”。

---

# 6. 三猫爪专项验收

每关至少跑出两种不同的 3 Paw 路线，才视为“重玩价值成立”。

推荐路线组合：

```text
SAFE + BALANCED
或
BALANCED + RISKY
```

禁止把 3 Paw 绑定为单一路径。

### 保护条件

```text
mission_complete = true
AND ninja_hp >= 2
```

第三关再额外允许：

```text
boss_mechanics_success >= 2
```

其余条件从 A–F（第三关 A–G）中满足 4 项。

---

# 7. 首通 Gate

每关首轮 8 人样本建议采用：

### 理解 Gate

至少 6/8 能说出这关的主决策。

### 行为 Gate

至少 5/8 在第二次尝试时主动改变策略。

### 多解 Gate

至少 3/8 能在无提示情况下找到第二种有效处理路线。

### 失败 Gate

随机抽 5 次失败，至少 4/5 能说出下一次准备改变的具体行为。

---

# 8. 路线成立判定

路线不是“理论上可行”就算成立。

### SAFE 成立

8 名新玩家中至少 6 人能理解并完成稳定路线。

### BALANCED 成立

8 名测试者中至少 4 人自然产生该路线；若 0–1 人主动采用，说明它可能没有足够的视觉 / 状态反馈。

### RISKY 成立

不要求新玩家首通就发现，但熟练玩家第二轮至少 2/4 应能主动尝试。

RISKY 如果只有“故意挨打”才能成立，视为失败设计。

---

# 9. 调参决策树

```text
玩家看不懂
→ 修视觉 / 路线 / State Feedback

玩家看懂但来不及
→ 调主时间杠杆

玩家会做但只会一种解
→ 增加另一条状态依赖 / Shortcut

玩家能找到两解但三爪只奖励安全解
→ 修 ScoreRule

玩家反复随机试
→ 因果反馈不够清楚

玩家首通太顺无重玩欲望
→ 增加固定 Variant / RISKY 路线
```

禁止第一反应：

```text
“玩家失败了 → 加时间”
```

---

# 10. 最终通过标准

12 关全部同时满足：

```text
[ ] 主决策可一句话解释
[ ] SAFE 路线成立
[ ] BALANCED 路线成立
[ ] RISKY 路线具有合理收益
[ ] 至少两种 3 Paw 路线
[ ] 失败原因可解释
[ ] 不依赖随机事件
[ ] 不需要新增核心操作
[ ] LevelValidator 全绿
[ ] Result / Save 正常
```

只有满足上述条件，关卡才进入最终美术锁定。
